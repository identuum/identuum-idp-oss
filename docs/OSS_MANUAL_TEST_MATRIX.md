# IDP OSS — Manual Test Matrix

Operator-practical manual test rows for `identuum-idp-oss`, paired with the
existing automated coverage. Generated by
`agent-a-20260620-idp-oss-ce-manual-test-matrix`.

Scope: only currently-implemented OSS functionality. Surfaces that are
CE-only (license envelope, claim flows, anomaly, system audit chain, MFA
disable refusal, deferred `/account/settings?tab=mfa` enrollment) are
NOT in this matrix; they live in [CE_MANUAL_TEST_MATRIX.md](../../identuum-idp-ce/docs/CE_MANUAL_TEST_MATRIX.md).

Default targets (override via env): IDP `http://127.0.0.1:7113`; UI
`http://127.0.0.1:7104`; Postgres `127.0.0.1:5513`.

**Secret-safety contract.** This document contains NO real passwords, setup
tokens, license envelope contents, cookies, JWTs, TOTP secrets, recovery
codes, private keys, or DB URLs. The "Manual steps" column references where
to obtain credentials (operator-controlled local files); operators MUST
never paste any of those values into a bug report, screenshot, log, or chat.

## Matrix

### OSS-1 — First-run setup wizard (single-organization)

**Manual steps.** From a fresh DB volume, browse to `/setup` on the UI; paste
the setup token printed by `identuum --setup --plain`; create the single
site_admin row.

**Expected.** Wizard advances through email → password → MFA enrollment
→ recovery codes → `setup_complete=true` on `GET /api/setup/status`.

**Auto.** Go unit + integration tests around `internal/setup/wizard.go`
+ `internal/cli/setup.go` (covered by OSS `make verify`'s `go test ./...`).
**Browser:** env-gated OSS-1 wizard Playwright spec at
`identuum-ui/e2e/oss-setup-wizard.spec.ts` added by
`agent-a-20260620-idp-ui-oss-setup-wizard-playwright`. Env-gated
(`IDENTUUM_E2E_OSS_SETUP_WIZARD=1`) destructive ceremony — single test
drives token verify → admin email/password → submit → assert
`/api/setup/status` flips to `setup_complete=true`. Pre-flight gates
on `setup_complete=false` AND (soft) `distribution !== "ce"` so the
spec correctly defers if the operator pointed at a CE backend by
mistake. Spec runs once per freshly-provisioned OSS stack; subsequent
runs skip at the `setup_complete=false` gate. Pattern-identical to
the prior CE spec at `identuum-ui/e2e/ce-setup-wizard.spec.ts` minus
the CE-only `license_valid` pre-flight gate (the wizard's license
step is conditional on `distribution === "ce"` and never reached
against an OSS backend).

**Secret-safety.** Setup token is single-use, plaintext-only-in-CLI-out.
Never copy/paste into reports.

### OSS-2 — Site-admin login (email + password + TOTP)

**Manual steps.** Browse to `/login`; submit email + password; complete
the TOTP challenge. Expect redirect to `/site-admin` (or the role-routed
landing per `src/lib/role-routing.ts`).

**Expected.** HTTP 200 + cookie session set + role `site_admin` carried
on subsequent `GET /api/v1/profile`.

**Auto.** Go integration tests in `internal/handlers/auth_*_test.go`
(covered by `make verify`). UI side: `identuum-ui/e2e/site-admin-*.spec.ts`
relies on the same login helper that the customer-smoke spec uses.

**Secret-safety.** Site-admin email + password + TOTP live in operator's
local env file (`.env.playwright.local` or shell exports). Never logged.

### OSS-3 — MFA enrollment via the login flow (pending-session shape)

**Manual steps.** As a user whose MFA is required-but-not-enrolled, log in;
the IDP returns a pending `session_id` + 401 with
`mfa_enrollment_required:true`. The UI's `MFAEnrollForm` drives
`POST /api/v1/auth/login/mfa/enroll/initiate` then `/complete`.

**Expected.** Enrollment succeeds → recovery codes displayed once →
subsequent login enforces TOTP.

**Auto.** Go integration tests in `internal/handlers/auth_mfa_enroll_test.go`
+ adjacent files (covered by `make verify`). UI vitest pins in
`identuum-ui/src/__tests__/idp-client-mfa-enrollment.test.ts` (the
`mfaEnrollInitiate` + `mfaEnrollComplete` describes; ~13 source-invariant
pins ensure the wire shape stays correct).

**Note.** OSS does NOT mount the cookie-session `/api/v1/mfa/setup/*` aliases
that CE adds — this is intentional (OSS/CE parity decision, recorded
in the maintainers' wiki, private).

**Secret-safety.** TOTP secret lives in the QR / `otpauth_url` shown ONCE
in the browser. Recovery codes shown ONCE. Never reproduce in reports.

### OSS-4 — Capability discovery: `GET /api/v1/component`

**Manual steps.** Unauthenticated `curl http://127.0.0.1:7113/api/v1/component`.

**Expected.** HTTP 200 + JSON body carrying `license: { license_type: "oss", status: "valid" }`
+ a stable set of capability booleans (the static OSS payload defined at
`internal/api/router.go:912-920`).

**Auto.** Go test against `componentHandler` (covered by `make verify`).
The customer-smoke Group 1 backend agreement tests (CE-side) also verify
the field shape at `identuum-ui/e2e/ce-customer-smoke-license-status.spec.ts`,
but the OSS payload is static — no live-state drift.

**Secret-safety.** Endpoint is unauthenticated by design; no secret material
returned.

### OSS-5 — Profile + sessions + change-password (cookie self-auth)

**Manual steps.** As a logged-in user, browse `/account/settings` and exercise
the four built-in tabs (password, sessions, passkeys, MFA). Submit a password
change; revoke another active session.

**Expected.** Password change returns 200 + session NOT revoked (per existing
contract); session revoke returns 200 + the revoked session disappears from
the list.

**Auto.** Go integration tests in `internal/handlers/auth_change_password_test.go`
+ `auth_sessions_list_test.go` + `auth_sessions_revoke_test.go` (covered by
`make verify`). UI Playwright: `identuum-ui/e2e/account-settings.spec.ts`
(passkey + tab routing surface).

**Browser:** env-gated rotate-and-rotate-back Playwright spec at
`identuum-ui/e2e/oss-change-password.spec.ts` added by
`agent-a-20260620-idp-ui-oss-change-password-playwright`. Env-gated
(`IDENTUUM_E2E_OSS_CHANGE_PASSWORD=1`) destructive ceremony — single
test drives login → submit change-password (original → runtime-
generated temp) → assert success panel + "All sessions revoked" →
re-login with temp → verify old password no longer works → re-login
with temp → rotate back (temp → original) → verify original works.
Cleanup-safe try/finally tracks `passwordKnownToWork` so a worst-case
mid-rotation failure attempts a best-effort rotate-back. Operators
run against a DISPOSABLE test user (NOT real site_admin) on a
freshly-provisioned OSS stack; the test user must have
`mfa_enabled=false` because the spec re-logs in 3+ times and would
exhaust a TOTP replay window.

**Secret-safety.** Old + new passwords live in the form only for the duration
of the submit. The UI never persists.

### OSS-6 — Logout + cookie revocation round-trip

**Manual steps.** As a logged-in user, submit `POST /api/v1/logout` (the UI's
account-menu "Sign out" item). Reload `/account/settings`; expect redirect
to `/login?reason=session_expired`.

**Expected.** Original cookie is dead → subsequent `/api/v1/profile` returns
401.

**Auto.** Go integration test for `/api/v1/logout` (covered by `make verify`).
The CE customer-smoke integration suite section "Logout round-trip" at
`scripts/customer-smoke-accept-integration.sh:1082` covers the same contract
against CE; OSS shares the helper code.

**Secret-safety.** Cookie value never appears in logs.

---

### OSS-7 — Passkey enrollment + assertion (WebAuthn)

**Manual steps.** From `/account/settings?tab=passkeys`, register a passkey;
log out; log back in selecting the passkey credential.

**Expected.** Enrollment shows the new credential in the list; passkey-based
login bypasses TOTP.

**Auto.** Go integration tests in `internal/handlers/webauthn_*_test.go`
(covered by `make verify`). UI Playwright `account-settings.spec.ts` pins the
surface RENDER (does NOT call `navigator.credentials.create` per the
spec's documented limit).

**Browser:** end-to-end WebAuthn ceremony Playwright spec at
`identuum-ui/e2e/passkey-flow.spec.ts` (5 tests T1-T5) using the CDP
`WebAuthn.*` domain via `BrowserContext.newCDPSession(page)` to install a
virtual authenticator (ctap2 / internal transport / hasResidentKey /
hasUserVerification / automaticPresenceSimulation). T1 clean slate;
T2 register a passkey; T3 credential persists after page reload; T4
sign in with registered passkey; T5 delete registered passkey.
Chromium-only (CDP `WebAuthn` domain is not available in Firefox/WebKit;
`playwright.config.ts` already configures Chromium as the sole project).
Discovered + matrix-row correction landed by
`agent-a-20260620-idp-ui-oss-webauthn-playwright-discovery` — the OSS-7
"gap" listed in the 2026-06-20 morning matrix was inaccurate: the spec
has been present since at least 2026-06-05, and the morning-of-2026-06-05
backend blocker (missing `UIPublicBaseURL` wiring in
`cmd/identuum-idp/main.go`) was already resolved by the
`internal/runtime/webauthn_ui_origin.go` helper that wires
`resolveUIPublicBaseURLForWebAuthn` into `runtime.go:614`'s
`WebAuthnServiceConfig`. Runs against the OSS dev stack on
`127.0.0.1:7113` (IDP) + `127.0.0.1:7104` (UI); skips cleanly via the
existing `skipAuthTests` gate when `IDENTUUM_TEST_SITE_ADMIN_PASSWORD` /
`_TOTP_SECRET` env vars are absent.

**Secret-safety.** WebAuthn challenge / credential blob never read.
