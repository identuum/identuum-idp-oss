# identuum-idp-oss v0.5.0 — release notes

Proposed tag: `v0.5.0` on `main`. **The owner tags and publishes; nothing in
the repository performs either.** The publish workflow's binary-vs-tag gate
runs on the pushed tag.

## Theme: a second factor that behaves like one

Before this release a TOTP code could be replayed inside its own validity
window, the account password could disarm MFA, a session alone could mint a
fresh set of recovery codes (and a recovery code could then disarm the
factor), nothing bounded attempts at the recovery-code route, and a
cross-site form could log a victim's browser into an attacker's account.
Each is closed, each with a rule on the repository's rule floor, and none
changes an endpoint's path. The canonical endpoint count is 144, unchanged
(`go run ./tools/api-docgen --dry-run | grep -c '^  - id:'`).

Since `v0.4.0` (measured `v0.4.0..v0.5.0`, see the CHANGELOG for the counts
and their predicate), in the order an integrator meets them:

- **Login CSRF** (`d8d4459`). `POST /api/v1/auth/login`, the MFA verify and
  enroll-complete steps of that login, and the passkey login finish refuse a
  request that carries `Origin` without `Content-Type: application/json`:
  `403 {"error":"csrf_failed","reason":"credential_post_requires_json"}`,
  before the body is read. A browser fetch with JSON, and every client that
  sends no `Origin` (curl, server-to-server callers, the UI's server-side
  proxy), are unchanged.
- **TOTP single use** (`0429ce0`). Every TOTP proof the appliance accepts —
  login, the pending-login MFA step, step-up, enrolment completion,
  recovery-code regenerate, self-disable — is accepted once per
  `(user, step)`. A replay is refused exactly like a wrong code: same
  status, body and audit row. If the replay store cannot be consulted the
  proof is refused, never accepted.
- **`POST /api/v1/me/mfa/disable`** (`52b5d0e`) accepts a current TOTP code
  or a recovery code; the account password is no longer a proof. A client
  that still sends `password` has it ignored; a password-only request gets
  `401 invalid_code`.
- **`POST /api/v1/me/mfa/recovery-codes/regenerate`** requires
  `{"code": "<current TOTP>"}` (`22e1c06`); a recovery code is not accepted.
  A wrong code or a recovery code: `401 invalid_code`; no code at all:
  `400 code_required` (`f44d551`); a malformed body: `400 invalid_request`.
  The route is rate-limited per authenticated subject (`3bd83c0`), default
  5 requests per 15 minutes, `429` past it, configured by
  `IDENTUUM_IDP_RATE_LIMIT_MFA_RECOVERY_CODES_REGENERATE_REQUESTS` and
  `IDENTUUM_IDP_RATE_LIMIT_MFA_RECOVERY_CODES_REGENERATE_WINDOW`.
- **A new public symbol, `pkg/webauthn.ErrCredentialNotYours`** (`954b89f`):
  the refusal `Service.DeleteCredential` returns for an unknown or another
  user's credential id. It aliases the internal not-found sentinel, so no
  behaviour changes; seam-only callers can now `errors.Is` it. `pkg/` still
  holds the same six packages.
- **Operations.** Every 401 verdict is logged once on the security logger
  with its reason code, never the credential (`048ace0`). `GET /health`
  carries `X-Identuum-Brute-Force-Protection: disabled` while the test-only
  `IDENTUUM_IDP_INSECURE_DEV_MODE` hatch is on, and answers
  `Cache-Control: no-store` (`3fdce76`).
- **OIDC certification posture** (`3835d71`, owner decision P-062 (b)):
  discovery keeps `id_token_signing_alg_values_supported` `[EdDSA, ES256]`;
  RS256 is registrable per client and mintable on explicit operator request
  but never advertised, so the config certification plan's RS256-in-discovery
  condition is a recorded expected failure.

## Upgrade

**Migration `0040_totp_used_steps` applies on start**, like every migration.
It creates one table, `totp_used_steps (user_id UUID, step BIGINT,
expires_at TIMESTAMPTZ, created_at TIMESTAMPTZ DEFAULT NOW())` with primary
key `(user_id, step)` and a `step >= 0` check, and one index,
`idx_totp_used_steps_expires_at`. It stores only step numbers — no code, no
seed — and its rows are swept by the revocation cleanup ticker once a step
can no longer be accepted. No existing table changes. `Down` drops the index
and the table.

Clients of the two self-service MFA routes: send a current TOTP `code` to
regenerate recovery codes, and do not rely on the password to disarm MFA.
No dependency moved; Go 1.27.1, migrations `0001`–`0040`.

**Host listening address.** `deployment/docker-compose.yml` now publishes
7113 on `${IDENTUUM_IDP_BIND_ADDRESS:-0.0.0.0}` and 7104 on
`${IDENTUUM_UI_BIND_ADDRESS:-0.0.0.0}`. For a loopback-only install:
`IDENTUUM_IDP_BIND_ADDRESS=127.0.0.1 IDENTUUM_UI_BIND_ADDRESS=127.0.0.1
docker compose up -d`. The in-container listeners are unchanged. Measured
on the default: IPv4 only — `curl -6 http://localhost:7113/health` no
longer connects, where the previous bare `7113:7113` mapping also published
`[::]`.

**Do not run `docker compose down -v` against a live install.** The compose
file pins `container_name:` and volume `name:` values: every install on one
host shares them, and `down -v` under any project name deletes the
install's database and data volumes.
