# identuum-idp-oss v0.3.6 — release notes

Proposed tag: `v0.3.6` on `main`. **The owner pushes and publishes; nothing
in the repository performs either.** A local annotated `v0.3.6` tag exists so
the publish workflow's canonical binary-vs-tag gate has its input; pushing it
is an owner step.

## Theme: change your password, keep your seat

Self-service password change lands end to end:

- **`POST /api/v1/auth/change-password`** (authenticated, self-service
  only). Current password verified; per-org password policy enforced; the
  target is always the caller's own account — no user id travels on the
  wire. Opaque refusals: wrong current password, federated accounts, and
  passwordless rows all answer the same `403`.
- **R2 session revocation** — on success, every OTHER session dies
  (reason `password_changed`) and all OAuth refresh tokens are revoked;
  the session that made the change stays valid, so the user is not dumped
  mid-flow. The audit trail records exactly what was revoked.
- The UI's account-settings rotation, which has always called this route,
  now works against OSS — including the "All other sessions have been
  signed out." statement, which is verified true end to end (a second
  logged-in browser context is bounced to the login page by the change).

Also in this release: the toolchain moves to **Go 1.27.0**
(owner-directed; `go.mod` + the digest-pinned image builder together,
enforced by TOOLCHAIN-PARITY-1; no dependency changes), the customer
compose pins the published `identuum-idp-oss:v0.3.5` and
`identuum-ui:v0.2.0` images by digest, and the integration gate
serializes its test packages over the shared test database (a measured
cross-package race).
