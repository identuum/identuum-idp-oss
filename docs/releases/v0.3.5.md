# identuum-idp-oss v0.3.5 — release notes

Proposed tag: `v0.3.5` on `main`. **The owner pushes and publishes; nothing
in the repository performs either.** A local annotated `v0.3.5` tag exists so
the publish workflow's canonical binary-vs-tag gate has its input; pushing it
is an owner step.

## Security release — and what happened to v0.3.4

`v0.3.4` was tagged but **never published**. Its image was built by a
`golang:1.26.5-bookworm` builder while the host toolchain was already
go1.26.6, so the image — and only the image — carried the vulnerable 1.26.5
standard library. Every host-side gate (govulncheck, grype on host-built
binaries) was green; the publish workflow's Trivy gate caught the image with
**8 HIGH `gobinary` findings** and stopped the run before GHCR login
(run 32392773901; nothing was pushed). Public tags are never rewritten, so
the `v0.3.4` tag stays; the shipped release is `v0.3.5` — `v0.3.4`'s content
on the fixed toolchain. See `CHANGELOG.md` `v0.3.4` for the feature set that
ships first here (doctor, factory-reset, operator guide, wizard
adopt-and-reset, seal health-visibility, health/details, admin state).

## The fix

- Builder: `golang:1.26.6-bookworm`, digest-pinned
  (`sha256:116d58cb…89c6f36`); `go.mod`: `go 1.26.6`. No dependency changes
  (`go mod tidy -diff` empty).
- CVEs closed (all Go stdlib / x-net-via-stdlib, all fixed in 1.26.6):
  CVE-2026-33818 (encoding/asn1 DoS), CVE-2026-39821 (net/http + x/net/idna
  privilege escalation), CVE-2026-46600 (x/net dnsmessage DoS),
  CVE-2026-56853 (h2c DoS), CVE-2026-56858 (html/template XSS),
  CVE-2026-56859 (encoding/xml DoS), CVE-2026-56860 (net/url DoS),
  CVE-2026-56862 (crypto/tls KeyUpdate DoS).

## The guard

**TOOLCHAIN-PARITY-1** (unit, in `make verify` and CI): parses the
Dockerfile builder's Go version AND `go.mod`'s `go` directive; fails on any
skew and on an unpinned builder. Red-proved by lowering the builder back to
1.26.5 and watching the failure. Host/image toolchain skew can no longer
ship silently.

## Verification

Local rebuild of the release image (stamped `0.3.5`) scanned with the
publish gate's own shape — `trivy image --severity HIGH,CRITICAL
--ignore-unfixed --exit-code 1` — exit 0, zero findings in both the OS and
`gobinary` targets; the v0.3.4-toolchain image reproduces the 8 HIGH under
the identical scan. `make verify` and `make integration-test` green at the
release commit; rule ledger 86/86 armed and red-proved.
