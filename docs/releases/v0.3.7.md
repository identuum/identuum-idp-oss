# identuum-idp-oss v0.3.7 — release notes

Proposed tag: `v0.3.7` on `main`. **The owner pushes and publishes; nothing
in the repository performs either.** A local annotated `v0.3.7` tag exists so
the publish workflow's canonical binary-vs-tag gate has its input; pushing it
is an owner step.

## Theme: the tag the commercial edition pins

An intermediate release on the v0.3 train, cut so that identuum-idp-ce can
pin a TAG instead of a pseudo-version. CE pinned `v0.3.7-0.20260907101516-
f8a1e6a7656b` and compiled clean against it, but a pseudo-version makes the
Go toolchain validate the base tag by unshallowing its module-cache clone,
and on GitHub's runners (git 2.55.0) that step dies with `fatal: shallow
file has changed since we read it` — every CE CI run since the pin. A tagged
version needs no validation and no unshallow. `v0.4.0` waits for the
`pkg/` → `internal/` move of the three directories nobody outside this
repository imports (decision P-061); this tag does not, and the Go source
it tags is the same source CE compiled against (only records and prose lie
between `f8a1e6a` and this commit).

Since `v0.3.6` (measured `v0.3.6..v0.3.7`, see the CHANGELOG for the
counts), in the order an integrator meets them:

- **OpenID Connect and OAuth 2.1 surface.** Forced re-authentication
  (`prompt=login`, `max_age`); the `claims` request parameter, consent-gated
  and role-intersected; the full OIDC profile plus `address` and `phone`
  claims with real profile fields; honest `acr` — the performed context is
  stamped, `acr_values` is honored by step-up or refusal, a phishing-
  resistant rung (passkey step-up) is advertised, and an upstream `acr` the
  ladder does not recognise is ASSUMED and never stamped; request objects
  by value (verified against registered keys, or unsigned; `request_uri`
  refused); per-client PKCE and a testing-only RS256; consented ∩
  role-permitted scope stamped on authorization-code access tokens; replayed
  authorization codes revoke what they minted.
- **Agent communication (AYGHU).** The AgentCommunicationAuthorization
  aggregate, its org_admin own-org admin API (create, list, get, revoke — no
  existence oracle), DPoP-bound participant tokens via client credentials,
  observable revocation of issued participant `jti`s, introspection judged
  against the authorization, and service accounts that carry their creating
  org_admin as owner. Migrations 0037–0039 carry it.
- **Authentication path truthfulness.** A store error on the auth path is a
  `503` with an ERROR log and a correlation id, never a `401`; a logout that
  cannot revoke still clears the cookie but never passes silently; browser
  and CSRF cookies take `Secure` from the request transport; `site_admin` is
  refused on the tenant OAuth-client, domains, protocol-settings, rbac-roles,
  service-accounts and api-resources surfaces; refusal shapes now tell the
  truth on several write paths (`400 weak_password`, sentinel `404` only for
  misses, `409` for duplicates, `500` for faults) — a client that matched
  the old statuses will notice.
- **Operators.** `rotate-encryption-key` (offline at-rest key rotation,
  atomic and resumable, with a doctor census and runbook); `audit-preupgrade`
  (the read-only sweep for rows the guards refuse); provenance announce and
  stale-binary refusal; `create-organization` with `admin_email` honored
  atomically; organization lifecycle filter and deactivated-org detail;
  restore of soft-deleted users; validated organization, user and client
  update paths that distinguish "not supplied" from "supplied blank";
  `INSECURE_DEV_MODE` as the named test-only rate-limit escape hatch.
- **Toolchain and dependencies.** Go 1.27.1; gin 1.12.0, pgx 5.10.0,
  goose 3.28.0, prometheus/client_golang 1.24.1, testify 1.12.1, zap 1.28.0,
  go-redis 9.22.0, miniredis 2.39.0, go-webauthn 0.18.0, jwt 5.3.1,
  x/crypto 0.56.0 (GO-2026-6303 fixed).
- **Verification machinery (repository-visible, not shipped in the
  binary).** The rule ledger grew from 88 to 254 armed rules (FLOOR 254);
  every `make verify` and every CI run leaves a committed gate-run record;
  `make witness` is the only way a witness commit is made; the e2e mint is
  computed by a reachability classifier; the checked-in OpenAPI document is
  compared byte for byte with its generator; a manual OpenID conformance
  harness (`make openid-conformance`).
