# identuum-idp-oss v0.6.1 — release notes

Tag `v0.6.1` on `main`. Published with the manual `publish-image.yml`
workflow (`version_tag: v0.6.1`, `latest_tag: false`); the index digest is
recorded where the compose file pins it. The binary embeds identuum-ui
`cf6575a` (tree digest
`b0eac627428a33c42df374573cf73b952c31f6aef874032b28ebd771a8b8e259`), the
tree identuum-ui `v0.3.1` publishes.

## Theme: fixes since v0.6.0

A patch release. Nothing a `v0.6.0` install relies on changes shape: same
URL, same single container, same database schema, same cookies.

- **A wrong method answers `405`.** A request whose path is registered
  under another method answers `405 Method Not Allowed` with an `Allow`
  header and `{"error":"method_not_allowed"}`, where it answered `404`.
  Through `/bff` the same request is refused `405` before the browser
  checks and is never forwarded. HEAD on a GET route, CORS preflight, UI
  pages and unregistered paths answer as before. `pkg/uiserve` gains
  `Options.AllowedMethods` (nil keeps every answer unchanged).
- **`migrate` says what it did**: `applied N migration(s) of M embedded;
  database at version V`. It printed `applied 0 migration(s) of 0 embedded`
  on an up-to-date database.
- **A claim link is no longer lost when creating its org_admin fails.** The
  claim consume runs in one transaction with the claim row locked; a failed
  create rolls the burn back and the link stays usable. Response bodies,
  email binding, single use and the attempt budget are unchanged.
- **Verification mail is rate-limited and audited.**
  `POST /api/v1/auth/resend-verification` and
  `GET /api/v1/auth/verify-email` had no limit and wrote no audit row.
  Resend and verify are now limited (below), and each sent mail and each
  verification is audited as `email_verification_resent` and
  `email_verified`, without the token or the address.
- **The embedded UI** (identuum-ui `v0.3.1`): dates in the viewer's zone
  with the zone named and the UTC time on hover; the account profile tab
  shows the saved profile (it rendered empty, and saving cleared it); a
  site_admin's sessions tab shows a notice instead of a load failure;
  `/logout` is a page whose form signs out; surfaces no edition serves are
  removed.

No migration (`0001`–`0040`, as in `v0.6.0`), no dependency moved, Go
1.27.1. The canonical endpoint count is 144, unchanged
(`go run ./tools/api-docgen --dry-run | grep -c '^  - id:'`). The full list
is in `CHANGELOG.md`, `## v0.6.1`.

### New rate-limit classes

| Route | Key | Default | Override (`_REQUESTS`, `_WINDOW`) |
| --- | --- | --- | --- |
| `POST /api/v1/auth/resend-verification` | client IP | 10 per 15 minutes | `IDENTUUM_IDP_RATE_LIMIT_EMAIL_VERIFICATION_RESEND_*` |
| `POST /api/v1/auth/resend-verification` | SHA-256 of the target address | 3 per hour | `IDENTUUM_IDP_RATE_LIMIT_EMAIL_VERIFICATION_ADDRESS_*` |
| `GET /api/v1/auth/verify-email` | client IP | 30 per 15 minutes | `IDENTUUM_IDP_RATE_LIMIT_EMAIL_VERIFY_*` |

An override can only raise a limit, as for the other classes. Past a
window the answer is the same `429 {"message":"Rate limit exceeded. Try
again later.","success":false}` with `Retry-After: 60` the other limiters
give. Known and unknown addresses are counted and answered alike.
`IDENTUUM_IDP_INSECURE_DEV_MODE=true` disables these limits with the
others; the published compose file does not set it.

## Upgrading from v0.6.0

The database, the data volume, the URL and the browser sessions carry
over unchanged.

1. **Back up.** Keep a copy of the current compose file and dump the
   database:

   ```bash
   cp docker-compose.yml docker-compose.v0.6.0.yml
   docker compose exec -T postgres pg_dump -U identuum_idp identuum_idp > identuum-idp-v0.6.0-backup.sql
   ```

2. **Replace the compose file with the `v0.6.1` one and recreate the
   container.** Only the `identuum-idp` image line and comments change;
   carry over any edits you made to the old file. The file is this
   release's `docker-compose.yml` asset (the install line,
   `releases/latest/download/docker-compose.yml`, serves the latest
   release's):

   ```bash
   curl -fsSLO https://github.com/identuum/identuum-idp-oss/releases/download/v0.6.1/docker-compose.yml
   docker compose up -d
   ```

   Never `docker compose down -v`: it deletes the install's database.

3. **Sessions.** Nobody signs in again: sessions live in the database and
   the cookies are unchanged. Accounts, organizations, clients, roles and
   enrolled authenticators are unchanged.

4. **Rate limits.** If an automation calls resend-verification or
   verify-email more often than the defaults above, raise the class with
   its override variables.

## Rolling back to v0.6.0

`v0.6.1` adds no migration, so a `v0.6.0` binary reads the same database.

```bash
cp docker-compose.v0.6.0.yml docker-compose.yml
docker compose up -d
```

Sessions carry over in both directions. Data written under `v0.6.1` stays,
including its `email_verification_resent` and `email_verified` audit rows.
`v0.6.0` again answers a wrong method `404` and carries no limit on the
verification routes. If the database itself must go back, restore the
step-1 dump into a stopped install; that loses everything written after
the dump.

## Known limitations

- **The published image does not record its commit.** `publish-image.yml`
  passes `VERSION` but no `COMMIT` build argument, so the image's build
  commit is the Dockerfile default `unknown`. The tag, the `sha-<commit>`
  image tag the workflow also pushes, and the provenance attestation still
  name the commit.
- **OSS sends no initial verification mail.** Nothing in the binary sends
  a new account its first verification link; a user gets one by asking
  `POST /api/v1/auth/resend-verification`.
