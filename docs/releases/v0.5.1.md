## Theme: first-run setup with an empty domain

`v0.5.0`'s first-run setup failed whenever the organization domain was left
empty — the ui wizard's domain field is optional — because the server used
the raw organization name as the domain, and any name with a space fails
organization validation. This release fixes that and changes nothing else
about the server's behaviour. The canonical endpoint count is 144, unchanged
(`go run ./tools/api-docgen --dry-run | grep -c '^  - id:'`).

- **An empty organization domain defaults to `slug(name) + ".local"`**
  (`6e0412a`). `POST /api/setup/complete` with `organization_domain` empty
  now creates the first organization under its name's slug: "Acme Corp" gets
  `acme-corp.local`, as the ui wizard documents. Before, the name itself was
  the domain, `"acme corp" has no dot` failed validation, and the request
  answered `400 setup_complete_failed`. An explicit domain is unchanged, and
  a resumed setup still reuses the organization a partial run left, whatever
  the new input says. A name with no letter or digit (for example "!!!") has
  no slug and therefore no default: it is refused as
  `400 {"error":"organization_domain_required"}` instead of the generic
  `setup_complete_failed`, and nothing is created. The slug is the one the
  organization service already uses for organization slugs; no second
  implementation was added.

## Upgrade

No migration (migrations `0001`–`0040`, as in `v0.5.0`), no dependency
moved, Go 1.27.1. An installation that completed setup is unaffected; one
that is still `setup_required` can now complete it with the domain left
empty.
