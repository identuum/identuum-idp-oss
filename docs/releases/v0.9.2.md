# identuum-idp-oss v0.9.2 — release notes

Tag `v0.9.2` on `main`. Published with the manual `publish-image.yml`
workflow (`version_tag: v0.9.2`, `latest_tag: false`); the index digest is
recorded where the compose file pins it. The Linux binaries are published
with `publish-binaries.yml` (`version_tag: v0.9.2`, `dry_run: false`). The
binary embeds identuum-ui `9cfd09b` (tree digest
`a90ba076fed87eb95fadb6c2d3691e1a802ce9c5c6f4c35ecd86b2bf6436947c`), the
tree identuum-ui `v0.6.2` publishes.

## Changes

- **/platform-status shows the commit.** The embedded UI is identuum-ui
  `v0.6.2`: the IdP's version is followed by the commit it serves, read
  from the public `/system/info` `build_commit` — "0.9.2 (commit <short>)".
- **CI runs the DB-backed tests under `-race` again.** The verify job's
  database settings had stopped reaching `go test -race` when its gate
  moved to `lictor witness run`, whose environment allowlist strips them;
  17 DB-backed tests skipped there under a green record (the Integration
  job still ran them). They now arrive as make command-line variables, and
  `IDENTUUM_IDP_REQUIRE_DB_TESTS` makes a missing database a failure.
- **Gate and CI tooling**, none of it in the binary: `make verify` runs
  through `lictor witness run --all` (lictor v0.4.4); the Integration job's
  record is lictor's and `make ci-fetch` fetches it; toolchain-parity
  prints each tool's resolved path; grype 0.120.0.

The full list is in `CHANGELOG.md` (`## v0.9.2`).

## Upgrading from v0.9.1

No migration; `go.mod` and `go.sum` unchanged; no route, field or response
shape removed or renamed (the canonical endpoint count stays 157). The
database, the data volume, the URL, the browser sessions and issued tokens
carry over.

1. **Back up** the compose file and the database:

   ```bash
   cp docker-compose.yml docker-compose.v0.9.1.yml
   docker compose exec -T postgres pg_dump -U identuum_idp identuum_idp > identuum-idp-v0.9.1-backup.sql
   ```

2. **Replace the compose file and recreate the container:**

   ```bash
   curl -fsSLO https://github.com/identuum/identuum-idp-oss/releases/download/v0.9.2/docker-compose.yml
   docker compose up -d
   ```

   Never `docker compose down -v`: it deletes the install's database.

3. **What changes for clients:** nothing; only the console's
   /platform-status page adds the commit.

## Rolling back to v0.9.1

The schema is the same, so restore the previous compose file and recreate
the container:

```bash
cp docker-compose.v0.9.1.yml docker-compose.yml
docker compose up -d
```

Sessions and tokens carry over. Restore the step-1 dump only if the
database itself must go back; that loses everything written after it.

## Known limitations

- **Requiring a verified email needs SMTP**; without it the setting is
  refused (`400 smtp_not_configured`) and the console disables it.
- **A claim link needs `IDENTUUM_IDP_UI_PUBLIC_BASE_URL`**; without it
  nothing is issued (`409 claim_url_unavailable`).
- **Separate sessions** (D-023). The console and the OpenID Connect
  sign-in keep separate sessions.
- **Single replica.** OSS enforces one serving instance (a DB lease); HA is
  a Professional+ capability.
